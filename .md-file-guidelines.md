# Markdown File Creation Guidelines

## Before Creating Any .md File

**ALWAYS ASK FIRST** before generating new .md files for tasks.

## Directory Rules

1. **dev-doc/** - AI-generated task documentation ONLY
   - Files created when resolving/performing tasks
   - Task checklists generated during work
   - Sprint notes created during sprints
   - Internal task notes
   - **DO NOT put user/API docs here**

2. **docs/** - User-facing and project documentation
   - API documentation
   - User guides
   - Architecture documentation
   - Database schemas
   - Technical decisions
   - Tool setup guides (for users)
   - Tutorials

3. **Root** - Essential project files only
   - README.md
   - PRD.md
   - RELEASE.md
   - SECURITY.md
   - (Ask before adding more)

## Process

1. **Ask**: "Should I create a .md file for [topic]?"
2. **Confirm location**: dev-doc/ or docs/?
3. **Create file**: Only after approval
4. **Update index**: Update dev-doc/README.md if needed

## Examples

✅ **Good**:
- "Should I create dev-doc/SPRINT1_NOTES.md for Sprint 1 tasks?"
- "Should I create docs/API_GUIDE.md for API documentation?"

❌ **Bad**:
- Creating .md files without asking
- Putting dev docs in root
- Creating files in wrong directory
